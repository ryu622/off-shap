# Stage 2(生成モデル版)設計メモ(2026-09-24、検討中)

Stage 1(`documents/stage1_worth.md`)の結果と、先行研究・hs-pinn の実装の確認を踏まえた、Stage 2 の設計の現時点の考えをまとめる。実装前の検討段階であり、未決事項は8節にまとめる。

## 1. 目的

Stage 1 で測れなかった「**デコイが守備を引きつけて、味方のスペースを作る効果**」(`stage1_worth.md` 7.6節の①)を、デコイ本人の貢献として評価する。

Stage 1 では、選手を消しても守備側は記録どおりの位置(引きつけられたままの位置)に残るので、デコイが作ったスペースは、それを押さえている別の選手の貢献になっていた。Stage 2 では「**その選手がいなかった世界で、守備がどう動いたか**」を生成し、その世界で v(S) を計算する。

## 2. 計画書 5.2節の「マスク学習による軌道補完」では目的を達成できない

計画書 5.2節は、「攻撃側選手をランダムな部分集合でマスクし、残りの選手・ボールの軌道から補完するモデル」(MIDAS、UniTraj などの枠組み)を想定している。しかし、軌道補完は「**見えていない選手の軌道を推定する**」技術で、Stage 2 で必要なのは逆である。

- 補完モデルで選手 i をマスクしても、i はその世界に「いる」前提のまま位置が推定されるだけで、守備側の反応は変わらない。Stage 1 と同じ限界が残る
- 必要なのは、**攻撃側とボールの動きを条件にして守備側の動きを生成するモデル**(ghosting の考え方)。選手 i を条件の入力から外して生成し直せば、「i がいなければ守備はこう動いた」を作れる

→ 計画書 5.2節は、この設計に合わせて修正が必要(8節 D)。

## 3. 決まったこと

### 3.1 生成するのは守備側だけ

- 外す攻撃側の選手は、**入力から消すだけ**。その選手の軌道を補完(推定)することはしない(補完すると「その選手がいる前提」になる)
- 残りの攻撃側とボールは記録どおりに固定する
- 守備側だけが「その選手がいない状況」に反応して動き直す

攻守を同時に生成しない理由:

1. **測りたい効果を切り分けるため**: 攻撃側も生成し直すと、「守備の反応が変わった分」と「味方の攻撃側の動きが変わった分」が混ざる。攻撃側を固定すれば、Stage 1 との差は「守備が反応するかどうか」だけになる
2. **ボールの扱いが格段に難しくなるため**: 攻撃側を生成し直すならボールも生成し直す必要があり、「誰にいつパスを出すか」という意思決定までモデル化することになる。7試合のデータでは難しい
3. **検証が難しくなるため**: 生成する部分が増えるほど実際の記録から離れ、その世界がもっともらしいかを示す負担が大きくなる

代償: 現実には攻撃側も反応する(デコイがいなければ別の味方が代わりに走り込んだかもしれない)。これを無視するので、デコイの効果を**過大評価する可能性**がある。限界として明記する(3.8節)。

| | 生成し直すもの | 固定するもの | 位置づけ |
|---|---|---|---|
| 2a / 2b | 守備側 | 残りの攻撃側、ボール | 主な結果 |
| 拡張(2c) | 守備側 + 残りの攻撃側 | ボール | 感度分析: 「攻撃側の反応も入れると、デコイの評価はどれだけ変わるか」。ボールを固定する矛盾は残る |
| 将来の課題 | 全員とボール | なし | 完全なシミュレーション。この研究の範囲外 |

### 3.2 モデル: 攻撃側とボールの軌道を条件にした守備側の軌道生成

- 各時刻の守備は、**その時刻までの**攻撃側とボールの動きだけを見て決める(未来を見ない)。攻撃側の未来の軌道まで入力に使うと、守備が「これから走り込む」ことを先に知っている状態になるため。1ステップずつ生成する形か、未来を見ないマスクを使う
- 入力: 守備側の初期状態(位置・速度)、各時刻までの攻撃側(外した選手を除く)とボールの位置・速度
- 出力: 守備側フィールドプレイヤーと GK の軌道

### 3.3 hs-pinn の実装から流用するもの・作り直すもの

hs-pinn(`/Users/ryuya/dev/hs-pinn`)の `TrajectoryBackbone`(`src/hs_pinn/model.py`)の構成:

```
入力: 奪取後1秒間(25フレーム)の攻撃側・守備側・ボールの位置と速度
  → 選手ごとの MLP(攻撃・守備・ボールで重み共有。特徴量は x, y, vx, vy, 種別の7次元)
  → GRU(1秒間を1本のベクトルに要約)
  → 全選手間の Self-Attention(1回。欠けている選手は key_padding_mask で無視)
  → MLP で、その後4秒間(101フレーム)の加速度を出力
  → ハード制約層(加速度 6 m/s²、速度 9 m/s、ピッチ境界)で積分して軌道にする
出力: 攻撃側または守備側(predict_side で切り替え)の4秒間の軌道
```

- modelA(λ = 0、守備側を予測)が、データ駆動の守備の ghost。守備側4秒間の平均位置誤差(ADE)は 2.49m(valid)
- 学習データは 502 シーン(奪取から5秒の固定窓)、試合単位で 5/1/1 に分割

| | 内容 |
|---|---|
| **流用する** | 選手ごとのエンコーダ(選手数が変わっても扱える)、マスク付き Self-Attention(攻撃側の選手を外す操作がマスクの切り替えでできる)、ハード制約層、学習ループの骨格(チェックポイント・実験条件のログ保存)、反実仮想パイプラインの構成(`scripts/counterfactual_pitch_control.py`: 守備を ghost に差し替えてピッチコントロールで比較)と限界の書き方 |
| **作り直す** | 入力の設計。modelA は「最初の1秒から、その後4秒を予測する」予測モデルで、**攻撃側のその後の動きを入力に使っていない**。攻撃側を1人外しても変わるのは最初の1秒間の入力だけで、その選手がその後走り込んだかどうかが守備の予測に反映されない。攻撃側とボールの軌道を毎時刻の条件にする形に変える |
| **作り直す** | データ変換。hs-pinn はイベント時刻から5秒の固定窓、off-shap はトラッキングの保持の切り替わりを始点にした可変長のシーン(`Scene`)で、速度の計算方法も違う |
| **追加する** | 生成モデル化(3.5節) |

### 3.4 学習の仕方

- **攻撃側全員を入力に入れた実データだけで学習する**。学習時に攻撃側をランダムに入力から外してはいけない
  - 実データの守備側は全攻撃側がいる状況で動いている。攻撃側 B を入力から外して正解を実際の守備の動きにすると、モデルは「見えない B がいるかのように守備を動かす」(B の影響を推測で補う)ことを学ぶ
  - そうなると推論時に B を外しても守備は B がいるかのように動き続け、Stage 1 と同じ結果に近づく
- 学習データは**カウンターのシーンに限らず、インプレーの区間すべて**から切り出して量を確保する(7試合で約14時間分のトラッキング)
- 分割は試合単位(`scene.SPLITS`: train 5試合 / valid J03WQQ / test J03WR9)
- 学習時に選手を外さないので、推論時に初めて選手を外すことになる。その出力の妥当性は別に確かめる(3.7節)

### 3.5 段階的に作る: 決定論的 → 生成モデル

- **2a: 決定論的なモデル**。hs-pinn の構成を流用し、入力を条件付きの形に変える。反実仮想のパイプライン(選手を外す → 守備を生成し直す → v(S) → φ)を最後まで通し、Stage 1 との最初の比較を出す。生成モデルでつまずいても成果が残るよう、リスクを下げる段階
- **2b: 生成モデル化**。2a に潜在変数を加えた CVAE が最小の変更。精度が足りなければ拡散モデルを検討する(ただし計算が重い)

生成モデルにすべき理由:

1. **平均の軌道では、デコイの効果が薄まる**。決定論的なモデルは起こりうる動きの平均を出力する。デコイが走り込んだとき守備には「ついていく」「持ち場に残る」の選択肢があり、平均を取るとその中間の、実際には誰も取らない位置が出る。守備が引きつけられる反応がぼやけ、Stage 2 で最も測りたい効果を過小評価するおそれがある。生成モデルなら両方の未来をサンプリングでき、v(S) をその期待値として計算できる
2. **反実仮想の不確実性を出せる**。サンプルごとに φ を計算すれば、φ のばらつきが出せる。先行研究がブートストラップと PRSV で不確実性を扱っていたのと対応する
3. **研究計画の主張と一致する**。計画書のタイトルと貢献は「生成モデルによる軌道補完」であり、決定論的なモデルだけで終わると主張と実装がずれる

2a と 2b の φ を比べて、理由1(平均の軌道では効果が薄まる)を実際に確かめる。これ自体が1つの結果になる。

生成モデルの難しさと対策:

| 課題 | 内容 | 対策 |
|---|---|---|
| 計算量 | サンプル数 K × 連合の数 × フレーム数の生成が必要。拡散モデルは1回の生成が特に重い | 軽い生成モデル(CVAE)、順列サンプリング、評価フレームを減らす(8節 C) |
| 学習データの量 | 生成モデルは決定論的なモデルより多くのデータが要る | インプレーの区間すべてから学習用の窓を切り出す(3.4節) |
| 検証 | 生成した軌道が妥当かを確かめる手段が限られる | 実データとの分布の比較、レッドカードのシーンでの確認(3.7節) |

### 3.6 v(S) と φ の計算は Stage 1 と同じにする

- 生成した守備側 + 固定した攻撃側・ボールで、ピッチコントロール × 相手陣内の xT(主指標 `xt_opp_half`)を計算する
- 0.5 秒ごとに φ を出し、シーン内で平均する
- 違いを「守備が反応するかどうか」だけにするため

### 3.7 検証

**原理的にできないこと**: 「このシーンで B がいなかったら守備はどう動いたか」は現実には一度も起きておらず、正解データが存在しない(因果推論の根本問題)。個々のシーンの反実仮想は検証できない。hs-pinn でも「ghost の軌道が個別に正しいことは直接検証できない」としていたのと同じ問題。

**間接的に確かめられること**:

| 優先度 | 検証 | 内容 |
|---|---|---|
| **必須** | 予測精度 | 攻撃側全員を入力したとき、別の試合の守備の動きをどれだけ正確に予測できるか。必要条件だが、反実仮想が正しいことの保証にはならない |
| **必須** | 挙動の確認 | 外した選手をマークしていた守備者が別の選手やボールのほうへ移るか、ボールから遠い選手を外しても守備がほとんど変わらないか、速度・加速度・選手間距離が実データの範囲に収まるか |
| **強く推奨** | 合成データでの検証 | 守備のルールを自分で決めたシミュレーション(例: 最も近い攻撃側をマークする、ゾーンを守る)でデータを作る。シミュレーションなら「B を消した世界」も動かせるので反実仮想の正解が手に入る。そのデータで学習させたモデルが、B を外したときの反応を再現できるかを確かめる。**手法の妥当性を示す唯一の直接的な証拠**。シミュレーションは本物らしくなくてよい。3.4節のような設計ミスを早く見つけられるので、**開発の早い段階で行う**。hs-pinn の合成データによる検証(`scripts/synthetic_validity_check.py` など)が参考になる |
| 推奨 | レッドカードのシーンとの比較 | 攻撃側10人のシーンが39件(うち33件は J03WN1)。1人外した入力での守備の動きが、実際に10人で攻めているシーンの守備の動きと**分布として**似ているか。退場後は戦術も変わるので補助的 |
| 時間があれば | 似た状況どうしの比較 | 「ある攻撃側の選手がそのエリアから遠く離れている(実質いない)」状況と比べ、モデルの反応が実際の守備の動きに近いか |

論文では、個々の反実仮想が検証できないことを限界として明記したうえで、合成データでの検証で手法の妥当性を、ほかの検証で実データでの振る舞いのもっともらしさを示す。Stage 1 と Stage 2 の差の主張も「モデルの仮定のもとで」という形で書く。

### 3.8 明記する限界

- 攻撃側の反応は固定している(SUTVA 違反)。デコイの効果を過大評価する可能性がある(3.1節)
- 個々のシーンの反実仮想は原理的に検証できない(3.7節)
- ピッチコントロールという指標の正しさに依存している(二重の近似)
- 学習時に選手を外さないので、選手を外した入力はモデルにとって未知の状況になる(3.4節)

## 4. ボールに関与した選手の扱い(案1・案2)

Stage 2 ではボールの軌道を記録どおりに固定するので、**ボールを持っていた選手を外すと、誰も持っていないボールが勝手に動く世界**になる。

**例(事例1、J03WMX_2_164290)**: Sané・Tel・Choupo-Moting・Upamecano がボールに関与し、Gnabry は逆サイドを走っていた(オフボール)。

- Sané を外すと、Sané がドリブルしていた軌道を誰もいないのにボールがたどり、Tel へのパスも誰も蹴っていないのに飛んでいく。守備モデルはボールのそばに必ず攻撃側の選手がいる実データで学習しているので、持ち主のいないボールは未知の入力で、生成された守備の動きは信頼できない
- Gnabry(オフボール)を外す場合は、ボールは Sané と Tel の間を実際どおりに動き、矛盾がない

これはモデルの精度の問題ではなく、「**ボールを持っている選手がいない世界」をどう定義するか**の問題である。ボールは誰かが運んでいるものなので、持ち主だけを消した世界は反実仮想として成り立たない。

Stage 1 にも同じ矛盾はあるが、影響は小さい。ピッチコントロールではボールの位置は各マスへの到達時間にしか使わず、ボールを持っている人がいるかどうかは計算に関係しないため。Stage 2 では守備モデルがボールの動きに反応するので、矛盾がそのまま結果に響く。

### 案1: 外すのはオフボール選手だけ

- ボール関与選手はシーン中ずっといるものとして固定し、オフボール選手の間で貢献を分ける
- 矛盾がない(ボールには常に持ち主がいる)
- オフボール選手は約7人なので、連合は 2⁷ = 128 通り
- 評価できるのはオフボール選手の貢献。Stage 2 の目的(デコイの効果)には合う
- Stage 1 も同じ定義で計算し直して比べる必要がある(保存済みの v(S) から再計算なしで出せる。`shapley.restricted_shapley` で固定メンバーをボール関与選手にするのと同じ計算)
- 主張の範囲は「全選手の貢献」から「**ボール関与選手の働きを所与としたときの、オフボール選手の貢献**」に絞られる

### 案2: 全員を外す対象にする

全選手を1つのゲームで評価する。ボール関与選手を外すときの定義として、次の3つを検討した。

**方法1(案2の中で推奨): ボール関与選手を外すときは、守備の反応を変えない(ハイブリッド)**

- 守備モデルには、ボール関与選手を常に見せる。生成し直すときに入力から外すのはオフボール選手だけ
- ピッチコントロール(v の計算)では、連合に入っていない選手はボール関与選手も含めて全員外す

| 外す選手 | 守備の動き | ピッチコントロール |
|---|---|---|
| オフボール選手(例: Gnabry) | 生成し直す(反応する) | 外す |
| ボール関与選手(例: Sané) | その選手がいる前提で生成する | 外す |

- 長所: 全員が1つのゲームに入る。守備モデルが持ち主のいないボールを見ることはない。実装も簡単。Stage 1 と Stage 2 の差はオフボール選手を外したときにだけ生じ、これは Stage 2 で測りたいもの(デコイの効果)そのもの
- 短所: ボール関与選手の貢献は Stage 1 と同じ静的な評価になり、「ドリブルで守備を引きつけた」効果はボール関与選手の貢献に入らない。ただ、ボールに守備が集まるのはボールを持っていれば誰でも起きることで、その選手固有の貢献かどうかはもともと曖昧なので、許容しやすい

**方法2: その瞬間の保持者だけを固定し、短い区間だけ生成し直す**

- 評価するフレームごとに、その瞬間ボールを持っている選手だけを常にいるものとする。ほかの選手は、後でボールを受ける選手も含めて外せる
- 守備はそのフレームから短い区間(1〜2秒)だけ生成し直す
- 長所: たとえば Tel がボールを受ける前に囮として走っていた時間帯の貢献も評価できる
- 短所: 短い区間の中で外した選手へのパスがあると矛盾が残る。区間が短いので、長い時間をかけて守備を引きつける効果は捉えにくい。実装も複雑
- 方法1の改良として後から足せる

**方法3(非推奨): 保持者がいなければボールを失ったとみなす**

- 保持者が連合にいない場合、v = 0(攻撃が成立しない)と定義する。先行研究の「誰も関与しなければアクションは存在しない」に近い
- 保持者の貢献が極端に大きくなり、ほかの選手の評価をかき消してしまう

### 案1と案2の比較

| | 案1: オフボール選手だけ | 案2(方法1): 全員 |
|---|---|---|
| ゲームの定義 | ボール関与選手は固定し、オフボール選手の間で分ける | 全員で分ける |
| 反実仮想の矛盾 | なし | なし(ボール関与選手を外すときは守備の反応を変えない) |
| 連合の数 | 約 2⁷ = 128 通り | 2¹⁰ = 1,024 通り(ただし守備の生成は約 128 回で済む。6節) |
| 評価できるもの | オフボール選手の貢献 | 全選手の貢献(ボール関与選手は静的な評価) |
| Stage 1 との比較 | Stage 1 も同じ定義で計算し直す | そのまま比べられる |
| 主張の範囲 | ボール関与選手の働きを所与としたときの、オフボール選手の貢献 | 全選手の貢献。Stage 1 との差はオフボール選手の反応から生じる |

**現時点の考え**: 案2なら方法1がよい。案1と案2(方法1)のどちらにするかは未決(8節 A)。

「ボール関与選手」をシーン単位で決めるか(一度でも触ればシーン中ずっと固定・守備モデルに見せる)、時刻ごとに決めるか(方法2の考え方)の選択もある。まずはシーン単位で始めるのが単純で、Stage 1 のベースライン(`stage1_worth.md` 6節)とも同じ定義になる。

## 5. 選手を「削除」するか「平均的な選手に置き換える」か

ここまでは、連合に入っていない選手を**削除する**(攻撃側が1人少ない世界を作る)前提で考えてきた。もう1つの選択肢として、**平均的な選手に置き換える**(その選手の代わりに普通の選手がいる世界を作る)方法がある。これは Shapley 値の分野で「基準(ベースライン)をどう置くか」と呼ばれる問題で、2つのやり方は答えている問いが違う。

### 5.1 2つのやり方が答える問い

| | 削除 | 平均的な選手に置き換え |
|---|---|---|
| 反実仮想 | その選手が**いなかったら**(攻撃側が1人少ない) | その選手の代わりに**普通の選手がいたら**(人数は同じ) |
| φ の意味 | その選手がいたこと自体の価値 | **普通の選手と比べて上乗せした価値** |
| φ の符号 | 本研究の v では必ず 0 以上 | マイナスになりうる(普通の選手より劣る場合) |
| 近い考え方 | 通常の Shapley 値(不在 = 0) | 野球の WAR(代替選手との比較)、SHAP の背景分布、Baseline Shapley(Sundararajan & Najmi 2020) |
| 先行研究との関係 | ― | 先行研究の「能力値の平均で差し替える」操作は、こちらの考え方に近い |

### 5.2 置き換えの長所

1. **守備モデルにとって見たことのある入力になる(Stage 2 では特に大きい)**。削除の最大の弱点は、「攻撃側が1人少ない入力を、モデルが学習中に見ていない」ことだった(3.4節、3.7節)。置き換えなら攻撃側の人数は常に同じなので、守備モデルは慣れた状況で守備を生成できる。反実仮想の信頼性の問題が大きく軽くなる
2. **現実的な反実仮想になる**。試合中に選手が1人いない状況はめったにない(レッドカードくらい)。「別の選手が出ていたら」は、監督が実際に考える問いである
3. **選手評価として意味がはっきりする**。削除では、ピッチ上にいるだけで押さえられるスペースも全部その選手の手柄になる。置き換えなら「普通の選手でも押さえられる分」が差し引かれ、その選手ならではの動きだけが評価される。デコイについても「普通の選手よりどれだけ多く守備を引きつけたか」になり、主張がより鋭くなる

### 5.3 置き換えの難しさ

**1. 「平均的な選手」の動きをどう作るか**

| 方法 | 内容 | 問題 |
|---|---|---|
| a. モデルで生成する(本命) | その場面・そのポジションで、普通の選手ならどう動くかを生成する | 攻撃側を生成するモデルが追加で必要 |
| b. ポジションごとの平均位置 | ボールの位置などに対する、そのポジションの平均的な相対位置を使う | 動きが単純すぎる |
| c. 他のシーンから借りる | 同じポジションの選手の軌道を別のシーンから持ってくる | その場面と合わない、ちぐはぐな動きになる |

a は、**計画書 5.2節にあった「マスクした選手の軌道補完」そのもの**である。2節で「軌道補完では削除の世界を作れない」と書いたが、置き換えの世界を作る道具としては筋が通る。この場合の流れは「対象の攻撃側選手をマスクして、普通の選手の軌道を生成 → それを入力にして守備側を生成」の2段階になる。

**2. 情報漏れに注意が必要**。補完するときに実際の守備側の動き(本物の選手に反応した動き)を入力に使うと、そこから本物の選手の動きが推測でき、「平均的な選手」が本物をまねてしまう。補完に使う入力は、守備側の反応を含まないもの(ボールと他の攻撃側、または場面の開始時点の状態だけ)に限る必要がある。

**3. 計算量が増える**。連合ごとに「どの選手を置き換えるか」が変わるので、攻撃側の生成も守備側の生成も、連合ごと(最大 1,024 通り)に必要になる。削除(案2・方法1)なら守備の生成は約 128 通りで済んでいた(6節)。

**4. 「平均」の定義に結果が左右される**。ポジション別の平均にするか、チーム内の平均にするか、リーグ全体の平均にするかで φ の値が変わる。7試合のデータでは、ポジション別の平均を安定して推定するのも簡単ではない。

### 5.4 Stage 1 での扱い

**Stage 1 だけで見れば削除のままで問題ない**。Stage 2 で置き換えを勧める一番の理由(守備モデルが見たことのない入力)は、学習したモデルがない Stage 1 には存在しない。ピッチコントロールは数式なので、選手を1人消した計算も数学的にきちんと定義されている。

ただし、次の2点に注意する。

- **解釈上の注意**: 削除の φ には**ポジションの役割による分**も含まれる。`stage1_worth.md` 6節のポジション別の結果で FW・ウイングの φ が高く CB が低いのは、「前線にいる役割だから、誰がそこにいても相手陣内のスペースを押さえられる」分も含んでいる。Gnabry が高く評価されたことも、一部は FW という役割によるものかもしれない。逆サイドへの走り込みが普通の FW より優れていたかどうかは、置き換えで初めて言える
- **Stage 1 と Stage 2 の基準をそろえる**: 研究の中心の主張は「Stage 1 と Stage 2 の差 = 守備の反応の効果」である。Stage 2 を置き換えにして Stage 1 を削除のままにすると、差に「基準の違い」も混ざる。Stage 2 で置き換えを採用するなら、Stage 1 の置き換え版も作り、比較は置き換えどうしで行う

**Stage 1 の置き換え版は安く作れる**。Stage 1 のピッチコントロールは「連合に入っている選手の分を足し合わせる」形で全連合をまとめて計算している(`stage1_worth.md` 1.2節)。置き換えの場合も「連合に入っている選手は本人、入っていない選手は代わりの選手」の分を足し合わせるだけなので、同じ行列の掛け算の形のまま計算できる。

```
A_S(t) = ∑[i ∈ S] aᵢ(t) + ∑[i ∉ S] aᵢ^rep(t)
       = ∑[i] aᵢ^rep(t) + ∑[i ∈ S] (aᵢ(t) − aᵢ^rep(t))
```

(aᵢ は本人、aᵢ^rep は代わりの選手がボールを収める速さ。)計算時間はほぼ変わらない。難しいのは「平均的な選手をどこに置くか」の定義で、これは Stage 2 と共通の設計判断なので、1回決めれば両方に使える。

### 5.5 設計の選択肢: Stage 1 と Stage 2 の両方で、削除と置き換えの2通りを出す

| | 削除 | 置き換え |
|---|---|---|
| **Stage 1**(静的) | 実装済み(`stage1_worth.md`) | 代わりの選手の位置の定義が必要。計算は安い |
| **Stage 2**(守備が反応) | 2a・2b の最初の形(守備の生成は約 128 通り) | 攻撃側の補完モデルが追加で必要(生成は最大 1,024 通り) |

4通りをそろえると、次の比較ができる。

- **行どうし(Stage 1 と Stage 2)**: 守備の反応の効果。基準をそろえて比べる
- **列どうし(削除と置き換え)**: 基準の選び方で選手評価がどう変わるか。「その選手がいたこと自体の価値」と「普通の選手との差」の違い。ポジションの役割による分がどれだけあるかも分かる

### 5.6 現時点の考え

Stage 2 の信頼性という点では、置き換えのほうが筋がよい可能性がある。削除の最大の弱点(見たことのない入力)を根本から解消できるため。一方で、実装は重く(攻撃側の補完モデルが追加で必要)、「平均」の定義という新しい設計判断も生まれる。そこで、次の順で進める。

1. **2a は削除で作る**。最も単純で、Stage 1 とそのまま比べられるので、パイプラインを先に通せる
2. **置き換えを主要な比較として設計に組み込む**。攻撃側の補完モデルを作り、削除と置き換えで φ がどう変わるかを比べる(5.5節の表を埋める)
3. **どちらを主な結果にするかは、合成データでの検証の後に決める**。削除の場合に、見たことのない入力で守備モデルが破綻するかを合成データで確かめ、破綻するなら置き換えを主にする

## 6. 全体の流れ(案2・方法1、削除の場合)

```
各シーン・各評価フレームについて
  各連合 S について
    ① 守備モデルへの入力: 連合 S の攻撃側 + ボール関与選手全員(実際の軌道)+ ボール(実際の軌道)
    ② 守備側の軌道を生成する(2b ではサンプル K 本)
    ③ ピッチコントロールの入力: 連合 S の攻撃側 + ② の守備側 + ボール
    ④ v(S) = ピッチコントロール × 相手陣内の xT
  φ を計算し、シーン内で平均する(2b ではサンプルごとの φ のばらつきも出す)
```

守備モデルへの入力は「連合 S のオフボール選手の部分」にしか依存しないので、生成の回数は「オフボール選手の部分集合の数」(約 2⁷ = 128)で済み、1,024 回は要らない。

## 7. 進め方(案)

1. 合成データのシミュレーションを先に作る(小さく)。2a のモデルがルールを再現できるかを確かめる土台にする
2. 2a(決定論的な条件付きモデル)を実装し、予測精度と挙動の確認を行う
3. 反実仮想のパイプラインを通し、Stage 1 と比較する
4. 2b(CVAE)に拡張し、2a と比較する
5. 置き換え版(攻撃側の補完モデル)を作り、Stage 1・Stage 2 の両方で削除と比較する(5.5節)
6. レッドカードのシーンとの比較、必要なら 2c(攻撃側も生成し直す感度分析)
